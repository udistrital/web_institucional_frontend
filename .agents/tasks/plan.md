# Implementation Plan

Diagnóstico y decisión: `getFaculties()` ya cumple el contrato de devolver `[]` cuando Drupal falla o no trae `data`; el runtime error nace en `FacultiesSection`, que calcula siempre tres índices circulares y luego usa el resultado como `Faculty` aunque `faculties.length` sea `0`. La corrección se concentrará en la frontera de renderizado del componente, sin cambiar rutas ni introducir un test runner que el proyecto no tiene configurado.

- [x] 1. Hacer robusta la selección y navegación de facultades en `FacultiesSection`, sin cambiar el comportamiento para datos válidos.
      Normalizar dentro del componente la lista recibida para trabajar solo con facultades definidas y renderizables, y derivar de esa lista el tamaño usado por todos los mapas, puntos y controles. Mantener los hooks (`useState` y `useSwipe`) en un orden estable antes de cualquier retorno temprano; hacer que `move` no aplique módulo cuando la lista está vacía, y normalizar el índice activo si la cantidad cambia para evitar un punto seleccionado inexistente. Calcular los elementos visibles solo cuando haya facultades y conservar exactamente el carrusel circular actual: con 1 facultad se repite el único elemento en las tres posiciones, con 2 se alternan las dos facultades en tres posiciones y con 3 o más se muestran tres elementos consecutivos con vuelta al inicio. Usar la lista normalizada también para la cortina de escritorio y los indicadores, de modo que ningún `Link` reciba un objeto `undefined`.
      Files: `app/components/home/FacultiesSection.tsx`
      Verify: `npm run lint` — ESLint termina sin errores; `npm run build` — la aplicación compila sin errores de TypeScript ni de renderizado estático.

      Después de llamar los hooks, retornar una sección válida cuando no haya facultades, manteniendo el encabezado y el enlace general `/facultades`, pero reemplazando tarjetas, flechas y puntos por un mensaje claro como “Información no disponible” que explique que las facultades no pudieron cargarse. Marcar el mensaje con una semántica accesible de estado (`role="status"` y anuncio educado) y crear en `app/components/home/home.module.css` una clase específica que siga el patrón visual ya usado por `.emptyState` en `app/facultades/page.module.css` (fondo blanco, borde/acento institucional, texto legible y ancho contenido), sin alterar las reglas de facultades válidas.

Repetir la comprobación con el endpoint inaccesible para confirmar que el retorno vacío ocurre después de ejecutar todos los hooks y que la página principal continúa mostrando el resto de sus secciones.
