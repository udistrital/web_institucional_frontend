# Filtered faculty offers and shared faculty-page redesign

The change moves individual faculty pages from the global academic-offer loader to a server-only JSON:API query filtered by `field_facultad.name`, with an in-memory full-catalog fallback and the global catalog loader preserved. It also consolidates the seven routes on a shared hero, faculty breadcrumb variant, accessible level tabs, responsive program cards, and a faculty-labelled news section. The Server/Client boundary remains serializable, and the previous duplicate heading, nested main, and missing inactive-tab-panel findings are addressed. **Watch for:** **confirmed** the `Facultad Tecnológica` title cannot receive its approved red accent, **confirmed** the hover detail layer is stacked beneath the title layer, and **confirmed** the long faculty breadcrumb can overflow narrow viewports.

**Verdict**: NEEDS_CHANGES

## High-level view

The performance path is isolated from the global catalog: faculty and news start together, the filtered offer waits for the resolved faculty, and a failed or empty filtered response falls back to the full program collection. Production and development cache options remain attached to the initial collection request and pagination requests.

The shared page keeps Drupal access on the server and sends plain faculty/program DTOs to the client offer. **Confirmed** presentation gaps remain in title segmentation, hover detail stacking, and narrow-screen breadcrumb wrapping.

Lint passes with nine warnings in unchanged shared header/footer files. The production build compiles TypeScript, the shared template, and the faculty route modules, but cannot complete static export because the configured Drupal endpoint refuses connections and the existing calendar route fails prerendering; this is an environment limitation rather than a source regression.

### Faculty-specific JSON:API loading and fallback boundary

`cargarOfertaPorFacultad` adds the exact `filter[field_facultad.name]` query, verifies every normalized returned faculty against `slugFiltro`, and falls back to `obtenerProgramas()` when the filtered response is empty, incompatible, or throws. The fallback keeps `noDisponible` false when the full catalog succeeds, and only marks it true when both paths fail. `OPCIONES_CACHE` is used by the first collection request and pagination, so the documented `no-store` development behavior and `revalidate: 3600` production behavior remain in the new path. `FacultyPage` retains the final slug filter before grouping, while `app/nuestra-universidad/oferta-academica/page.tsx` continues to call `cargarOfertaAcademica`.

### Shared Server/Client composition and accessibility fixes

The client receives only serializable faculty, level, and program values. **Confirmed** its tabs render every panel and pair each `aria-controls` value with an existing ID, hiding inactive panels instead of removing them. **Confirmed** the remaining title defect is at `app/facultades/components/faculty-heading.ts:38-40`: the `prefixMatch` regular expression requires `de` or `del`, so the fallback title declared for the Tecnológica route cannot match the approved `tecnológica` term and returns the whole heading as an unaccented segment.

### Card reveal and responsive layout

**Confirmed** the offer CSS places `.programTitle` at `z-index: 4` (`faculty-academic-offer.module.css:152-167`) above `.programReveal` at `z-index: 3` (`:179-196`). Because the reveal is bottom-aligned and reserves bottom padding, the title covers the lower detail rows instead of exposing a complete Jornada/Modalidad reveal on hover or focus. The grid breakpoints otherwise provide the requested four-column desktop, two-column intermediate, and one-column mobile layout.

### Breadcrumb behavior and unchanged consumers

The new `faculty` branch is isolated from the existing `default` and `onDark` branches and is rendered immediately after the faculty hero. **Confirmed** the `<ol>` at `components/common/bread-crumbs/bread-crumbs.tsx:29` uses `display:flex` with `gap` but neither `flex-wrap` nor a narrow-screen overflow strategy, so the long route label can force horizontal overflow. The global header, `NewsSection`, and global catalog consumer are outside the changed behavior.

### Verification evidence

`npm run lint` completed with zero errors and nine pre-existing warnings in shared header/footer code. `npm run build` compiled successfully through TypeScript and page-data collection, then exited during prerender because Drupal returned `ECONNREFUSED`; the reported failing route is the existing `/nuestra-universidad/calendario-academico`, so a full static-output assertion for all seven faculty pages remains unavailable until Drupal is running. No frontend test runner is configured in the task context, so fallback and responsive behavior were reviewed from source rather than automated component tests.
