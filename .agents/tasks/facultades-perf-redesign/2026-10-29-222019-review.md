# Filtered faculty offers and shared faculty-page redesign

The seven individual faculty routes now use a server-side JSON:API query filtered by the exact faculty name, with a full-catalog fallback, while the global academic catalog continues using its existing loader and vocabulary requests. The shared page composes the faculty hero, faculty breadcrumb, accessible academic-offer tabs and responsive program cards, then labels the news section with the faculty name. The final fixer preserves the approved title exception for `Facultad de Artes - ASAB`, keeps card titles visible while details reveal, and makes no-link cards readable without keyboard-only hover state. **Watch for:** **confirmed** `npm run build` still cannot complete static prerendering because the configured Drupal endpoint refuses connections at the pre-existing calendar route; rerun the build with Drupal available for full route-output evidence.

**Verdict**: APPROVED

## High-level view

The faculty data path is isolated from the global catalog. Faculty and news resolution starts together, the filtered program request waits for the resolved faculty title, and an empty, incompatible or failed filtered response falls back to the complete program collection. Production revalidation and development no-store behavior are retained.

The shared page keeps Drupal access in server-only services and passes serializable faculty and program data to the client offer component. The hero has one accessible heading, the faculty breadcrumb is scoped to its new variant, and the seven route adapters share one implementation without changing the global header or news component.

The offer uses visible levels only, ARIA-linked tab panels, four/two/one responsive cards, accessible image fallbacks and the requested hover, focus and reduced-motion behavior. The title segmenter now handles connectorless `Facultad Tecnológica`, the explicit ASAB rule and unsafe-title fallback; the breadcrumb wraps long current-page labels.

### Faculty-specific JSON:API loading and global catalog boundary

`cargarOfertaPorFacultad` adds `filter[field_facultad.name]` to the existing `node--oferta_academica` collection, validates normalized results with `slugFiltro`, and derives levels, modalities and jornadas from those programs without querying taxonomy collections. An empty or incompatible filtered response follows the same full-catalog fallback as a request failure; `noDisponible` is set only when both collections fail. The collection and pagination requests retain `cache: "no-store"` in development and `revalidate: 3600` elsewhere.

The global route still calls `cargarOfertaAcademica`, including its vocabulary requests and existing result shape. The faculty page applies its final slug filter before grouping, so the filtered response cannot introduce programs from another faculty even if Drupal returns an unexpected resource.

### Server/client topology and page composition

`FacultyPage` starts `getFacultyBySlug` and `getNews` in the same `Promise.all`, then loads the offer only after the faculty title is known. The server-only service boundary prevents Drupal clients and raw response data from reaching `FacultyAcademicOffer`; the client receives plain faculty, level and program values.

The page renders the faculty breadcrumb after the hero and leaves the default and `onDark` branches unchanged. The title helper returns one segment list for one `h1`, keeps approved terms accent-colored only when separators are safe, and explicitly returns a black prefix plus red `ASAB` for `Facultad de Artes - ASAB`. The breadcrumb's wrapping current-page item prevents long faculty names from forcing a narrow viewport wider.

### Offer interaction, accessibility and external-link posture

The offer renders only levels with programs and limits the visible card set to four. Tabs retain `role="tab"`, `aria-selected`, `aria-controls`, roving tab focus and matching hidden panels. Program cards use a four-column, two-column and one-column grid, square media, accessible image fallbacks and a title layer above the animated detail layer. Linked cards reveal Jornada and Modalidad on hover or focus-within; cards without a program URL keep those details visible without pretending to be interactive. Reduced-motion rules remove image, reveal and control transitions.

Program URLs are normalized to HTTP(S) values in the server loader, and the catalogue CTA uses `_blank` with `noopener noreferrer`. No new authentication, token handling or client-side Drupal access was introduced by either feature.

### Verification and remaining environment limitation

`npm run lint` completed with zero errors and nine warnings in unchanged shared header/footer files. `npm run build` compiled successfully through TypeScript, CSS Modules, page-data collection and the faculty route generation. It then failed while prerendering the existing `/nuestra-universidad/calendario-academico` route because the configured Drupal endpoint returned `ECONNREFUSED`; no changed faculty route reported a compilation or type error before that external failure. **Confirmed** visual Drupal-backed verification and automated component coverage were unavailable in this environment.
