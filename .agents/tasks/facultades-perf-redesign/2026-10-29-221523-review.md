# Filtered faculty offers and shared faculty-page redesign

The change gives individual faculty pages a server-only JSON:API offer query filtered by `field_facultad.name`, with a full-catalog fallback, while leaving the global catalog on `cargarOfertaAcademica`. It also connects the seven routes to a shared hero, faculty breadcrumb variant, accessible level tabs, responsive program cards, and faculty-labelled news. The final implementation keeps Drupal access on the server and passes serializable DTOs to the client offer component. **Watch for:** **confirmed** the ASAB heading exception is not implemented as specified, and **confirmed** the card reveal hides the program title on touch layouts while cards without links have no keyboard focus target; the production build remains **confirmed** blocked by the unavailable Drupal endpoint at the pre-existing calendar route.

**Verdict**: NEEDS_CHANGES

## High-level view

The faculty-specific loading path is separated from the global catalog. Faculty resolution and news still start in parallel, the filtered offer starts after the faculty title is known, and failed or incompatible filtered data falls back to the complete program collection. Cache settings and the final slug safety filter remain in place.

The shared Server/Client composition keeps Drupal and fallback logic server-side, with matching hidden tab panels and an unchanged global catalog consumer. The default and `onDark` breadcrumb branches remain isolated from the faculty variant.

The remaining presentation gaps are concentrated in the program-card interaction and one explicit heading rule. The raised full-card reveal obscures the title on hover and whenever touch styles force it visible; the non-link article branch cannot receive focus for keyboard users.

<summary>Details</summary>

### Faculty-specific JSON:API loading and global catalog boundary

`cargarOfertaPorFacultad` adds the exact `filter[field_facultad.name]` request to the existing program collection, validates every normalized result against `slugFiltro`, and falls back to `obtenerProgramas()` when the filtered query fails, is empty, or returns incompatible resources. The faculty path derives levels, modalities, and jornadas from the returned program DTOs instead of calling taxonomy collections. `FacultyPage` keeps the final slug filter before grouping, while the global route still calls `cargarOfertaAcademica` and retains its vocabulary requests.

The collection requests use `no-store` in development and `revalidate: 3600` otherwise, including pagination requests. If both faculty and fallback collections fail, the loader sets `noDisponible` and the client renders the unavailable state.

### Server/Client boundary and page topology

`FacultyPage` resolves Drupal data in server code and sends only faculty and program presentation fields to `FacultyAcademicOffer`; no Drupal client or contact attributes cross the boundary. The seven route adapters pass only their folder slugs, and metadata uses the same server-side faculty lookup. The faculty breadcrumb branch is rendered after the hero, wraps long current-page labels, and leaves the existing `default` and `onDark` branches unchanged.

The tab buttons retain `role="tab"`, `aria-selected`, `aria-controls`, roving `tabIndex`, and keyboard movement. Every panel remains in the DOM with a matching ID and inactive panels use `hidden`.

### Heading segmentation and card interaction

The heading helper now accepts a connectorless `Facultad` prefix, which covers `Facultad Tecnológica`, and returns an all-black segment when separators are unsafe. Its general approved-term matching does not honor the separate ASAB rule: for the exact title `Facultad de Artes - ASAB`, the subject contains two approved matches and both become accent segments. The requested exception therefore still needs an explicit branch or equivalent segmentation rule.

The card image, title, and details share one square media box. The title is positioned at z-index 4, but the full-card reveal is positioned at z-index 5 and becomes opaque on hover, focus-within, and devices without hover. This makes the requested title unavailable visually in those states, especially on mobile. Cards with no program URL use an article with no focusable descendant, so keyboard users cannot trigger the focus-within path; the implementation needs a separate accessible treatment for that branch.

### Verification evidence

`npm run lint` completed with zero errors and nine warnings in unchanged shared header/footer files. `npm run build` compiled the application and TypeScript, then failed during static prerender because the configured Drupal endpoint returned `ECONNREFUSED` on the existing `/nuestra-universidad/calendario-academico` route. The build therefore does not provide a complete static-output assertion for the seven faculty pages in this environment, although no changed faculty route or type error was reported before the external failure. No visual Drupal-backed review was possible while the endpoint was unavailable.
